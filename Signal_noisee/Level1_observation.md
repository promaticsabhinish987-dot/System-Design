# Chapter 1: Reality Model

## Objective

Understand why signal exists and how to identify it in any domain.

---

# Core Principle

Reality contains many variables, but only a few variables significantly influence an outcome.

```text
Many Variables
      ↓
Few Important Causes
      ↓
Outcome
```

Signal extraction is the process of identifying those important causes.

---

# Definitions

## Observation

A fact or result that is noticed.

Examples:

* Website is slow
* Interview failed
* Revenue decreased
* User left application

Observation describes what happened.

Observation does not explain why it happened.

---

## Outcome

The final result produced by a system.

### Definition

An outcome is the observable result that we want to explain, predict, or improve.

Examples:

* Website response time
* Coding interview success
* Product sales
* Weight loss

### Key Rule

No outcome → No analysis.

No outcome → No signal.

---

## Cause

A factor that directly influences an outcome.

### Definition

A cause is a variable that changes the probability or magnitude of an outcome.

Examples:

Outcome: Website slow

Possible causes:

* Slow database query
* Network latency
* Large images

---

## Variable

Any factor that can affect a system.

### Definition

A variable is any measurable or observable factor that may influence an outcome.

Examples:

* CPU usage
* Sleep hours
* Practice time
* Network speed

Reality contains many variables.

---

## Signal

### Definition

A signal is a high-impact cause that explains a significant portion of an outcome.

Characteristics:

* Strong influence
* Predictive
* Repeats across situations
* Worth attention

Examples:

Outcome: Coding interview success

Signals:

* Problem-solving ability
* DSA practice
* Communication

---

## Noise

### Definition

Noise is information or variables that have little or no influence on the outcome being studied.

Characteristics:

* Low impact
* Distracting
* Consumes attention
* Adds complexity

Examples:

Outcome: Coding interview success

Noise:

* Wallpaper color
* Keyboard brand
* Laptop sticker design

---

# Why Signal Exists

Signal exists because reality is uneven.

Not all causes contribute equally.

Example:

Website latency:

* Database query = 800ms
* Network latency = 20ms
* Browser rendering = 5ms

Database query dominates the outcome.

Therefore:

```text
Signal = Dominant Cause
Noise = Minor Cause
```

---

# Fundamental Law

Importance is always relative to an outcome.

Nothing is universally important.

Example:

Sleep

For athletic recovery:

* Strong signal

For frontend rendering:

* Noise

Therefore:

```text
Outcome determines signal.
```

---

# Signal Extraction Process

Step 1:
Identify the outcome.

Step 2:
List possible causes.

Step 3:
Measure influence of each cause.

Step 4:
Rank causes by impact.

Step 5:
Focus on highest-impact causes.

---

# Mental Model

```text
Outcome
    ↑
Dominant Causes
    ↑
Variables
```

Signal extraction moves upward:

Variables → Causes → Outcome

---

# Key Questions

1. What is the outcome?
2. What system produced it?
3. What variables affect it?
4. Which variable has the highest influence?
5. Which variables can be ignored?

---

# Common Mistakes

### Mistake 1

Looking for solutions before defining the outcome.

### Mistake 2

Confusing correlation with causation.

### Mistake 3

Treating all variables as equally important.

### Mistake 4

Collecting information instead of identifying causes.
